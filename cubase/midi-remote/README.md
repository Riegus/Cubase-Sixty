# MIDI Remote scripts

The Cubase side of Cubase-Sixty: one MIDI Remote script per surface. They speak the MIDI defined in [`../docs/bridge-midi-protocol.md`](../docs/bridge-midi-protocol.md) and map it to Cubase's mixer and transport.

| Folder | Script | Surface | What it does |
|--------|--------|---------|--------------|
| `UF8/` | `CubaseSixty_UF8.js` | SSL UF8 | Eight faders with touch (Touch automation works), pan on the V-pots (value and bar on each strip's display), SEL / SOLO / CUT with LEDs, top soft keys toggle record-enable (dark on strips that cannot record), V-pot push opens the channel editor, bank left / right (bank-right stops at the bank where the last track is on strip 8), Page left / right (one channel), follows the track selection (also at start-up), automation Read / Write on the selected track, automation mode keys (Off = Cross-Over, Trim, Latch, Touch), zoom pad (zoom, vertical zoom, centre = open / close editor), FLIP, foot switches (play / record), track names and colours on the scribble strips, fader level in dB and stereo meters per strip. |
| `Helper/` | `CubaseSixty_Helper.js` | none | Holds the UF8 script's large channel lists (all channels, recordable channels) and sends their names to the bridge, which passes them on to the UF8 script. A separate device, so that the UF8's bank moves do not pay for the lists (see below). Detected automatically like the others (ports `Cubase-Sixty Helper to / from Cubase`). |
| `UC1/` | `CubaseSixty_UC1.js` | SSL UC1 | The SSL plug-ins on the **selected track**: the Channel Strip knobs and buttons drive its channel strip (Channel Strip 2, 4K E / G / B, SSL 360 Link), the seven Bus Comp knobs and Bus Comp IN a Bus Compressor 2 (or SSL 360 Link Bus Compressor) anywhere in the project, picked with the Bus Comp encoder (the large name row shows its track and the neighbours; until one is picked, the one on an output channel, else the first), so it stays put while you select other tracks; Channel IN = the strip's own bypass, Fine = finer steps, CHANNEL encoder = previous / next track, SOLO / CUT / polarity of the track, Solo Clear. Knob rings follow the plug-ins' values (also when changed with the mouse or by automation), button LEDs the switches, the display shows the track name and colour, the plug-in (model field) and the value being turned; the 7-segment shows the channel's MixConsole number. **Without an SSL channel strip** on the track (model field "CUBASE"), the Channel Strip section drives Cubase's own: Input Trim = input gain, High Pass / Low Pass = low cut / high cut (on when turned, off at the end of the range), LF / LMF / HMF / HF = EQ bands 1–4 (a band switches on when turned), LF / HF BELL = bands 1 / 4 between shelf and bell (Parametric II), EQ IN = EQ bypass. Dyn knobs: the strip's compressor (Standard: threshold / ratio / release; Tube and Vintage, which show no threshold or ratio: Ratio knob = Input Gain, Threshold knob = Output Gain); Gate knobs: the Noise Gate; F.ATT switches the section's Release knob between release and attack (lit = attack). DYN IN = compressor bypass, EXP = gate bypass (the Noise Gate has no expander mode), SC LISTEN = the gate's side-chain monitor. A missing module is loaded on the spot: DYN IN or a Dyn knob loads a compressor (DYN IN: Standard; a Dyn knob, or DYN IN held 0.6 s: a picker, Dyn knobs step through Standard / Tube / Vintage, CONFIRM or DYN IN loads, BACK cancels; held on a loaded one, it changes the type), EXP or a Gate knob loads the Noise Gate. |
| `UF1/` | `CubaseSixty_UF1.js` | SSL UF1 | One strip that controls the **selected track**: fader with touch, SOLO / CUT / SEL, pan on the knob above the fader, MODE (hold) + display soft keys = view: DAW (V-pots 1–4 = sends 1–4, or 5–8 after the 5–8 key; turn = level, push = on / off), SENDS (the same, with all four sends' names, levels and bars in the display's V-pot cells) or PLUGIN (V-pots = Quick Controls 1–4 / 5–8 of the focused plug-in, or of the track), MASTER = the strip on the main output, SHIFT + transport soft keys / Cycle / Click = automation Read, Write, Cross-Over, Trim, Latch, Touch, channel encoder and ARROW = previous / next track, BANK = banks the UF8, jog wheel = nudge cursor (SHIFT: markers), SHIFT + ARROW = bar steps, shuttle (SHIFT + SCRUB), BYPASS = all inserts of the track, FLIP, 360° = swap time formats, NAV cross = zoom (centre = open / close editor), transport keys (rwd, ffw, stop, play, record, cycle, click) with LEDs. The display shows the track name, level, colour, and a value line with pan, or a send for 3 seconds after it is turned, a stereo meter, the transport position and the selected track's number (as in the MixConsole). Scrubbing goes through a Mackie Control device (setup step 6). |

Tested with Cubase 15 Pro on Windows. The folder names, the file names and the device names in the scripts must match (`CubaseSixty` / `UF8` / `UF1`), or Cubase will not list the script.

## Setup

1. **Install loopMIDI** (https://www.tobias-erichsen.de/software/loopmidi.html). The bridge uses its driver to create the MIDI ports itself, so you do not create any ports in loopMIDI. The ports are `Cubase-Sixty UF8 to Cubase`, `Cubase-Sixty UF8 from Cubase`, `Cubase-Sixty UF1 to Cubase` and `Cubase-Sixty UF1 from Cubase` ("to Cubase" is where the bridge writes and Cubase reads, "from Cubase" the other way round). They exist only while the bridge runs. If you made ports with these names in loopMIDI earlier, delete them. (Without the driver library, or with `--loopmidi`, the bridge uses ports you create in loopMIDI with exactly these names instead.)
2. **Keep the ports out of All MIDI Inputs.** Once the bridge is running, open *Studio > Studio Setup > MIDI > MIDI Port Setup* in Cubase and untick **In 'All MIDI Inputs'** for all the ports. Otherwise a selected instrument or MIDI track receives the controller messages as played notes. Cubase may tick it again for a port it sees as new, so check after the first start.
3. **Install the scripts.** Run
   ```
   powershell -ExecutionPolicy Bypass -File cubase\midi-remote\tools\install-scripts.ps1
   ```
   It copies each script to `<Documents>\Steinberg\Cubase\MIDI Remote\Driver Scripts\Local\CubaseSixty\<UF8|UF1|UC1|Helper>\` (it finds your Documents folder even when it is redirected to OneDrive) and removes the old `SSL` folder from earlier versions. If your Cubase driver-script folder is elsewhere, pass it with `-Destination "<path to ...\Driver Scripts\Local>"`. Run it again after each edit.
4. **Activate.** Restart Cubase, or press **Reload Scripts** in the MIDI Remote Script Console (turn on *Scripting Tools* from the context menu of the MIDI Remote info line). The script console should show `[CubaseSixty] script loaded`. In the MIDI Remote Manager each surface should show as connected. A stale entry named "SSL" from an earlier version can be removed there.
5. **Start the bridge before Cubase** (see [`../bridge/README.md`](../bridge/README.md)). Cubase activates the scripts when it sees the ports. If you restart the bridge, restart Cubase too.
6. **Add the Mackie Control device (UF1 scrubbing).** With the bridge running: *Studio > Studio Setup*, click **+** (top left, "Add Device"), choose **Mackie Control**. Select it under *Remote Devices* and set **MIDI Input** to `Cubase-Sixty MCU to Cubase` and **MIDI Output** to `Cubase-Sixty MCU from Cubase`, then **Apply**. Under *MIDI Port Setup*, untick **In 'All MIDI Inputs'** for the two MCU ports too. The bridge only uses this device for SCRUB and the jog while scrubbing.

## Testing without the hardware

`tools/test_bridge.py` plays the UF8 bridge (it needs the UF8 ports, so create two ports in loopMIDI with the UF8 names while testing, and do not run the real bridge at the same time): it sends fader, mute, solo, bank and transport messages to `Cubase-Sixty UF8 to Cubase` and prints everything Cubase sends back on `Cubase-Sixty UF8 from Cubase`, including the name and colour SysEx. It needs Python with `mido` and `python-rtmidi` (`python -m pip install mido python-rtmidi`).

```
python cubase\midi-remote\tools\test_bridge.py
```

Open the MixConsole while it runs, ideally with more than 8 tracks so banking is visible.

## Debug logging

Every script's log lines also go to the bridge, which writes them to `cubase\logs\scripts.log` with a timestamp and the script's name, so the Script Console is not needed (see the bridge README, Logs). Set `DEBUG = true` near the top of the UF8 script to log every fader, solo, mute, name and colour change. It is off by default because it is very chatty while a fader moves.

## Behaviour to know about

- **Implicit mute.** Soloing a track makes Cubase report `MUTE 1` for the other tracks, so the surface cannot tell implicit mute from an explicit one.
- **Empty strips.** A strip with no track sends an empty name and a colour with alpha 0; the bridge shows it blank.
- **Colours.** Cubase gives red, green and blue as 0 to 1; the script scales them to 0 to 127. Cubase only reports a colour when a track is selected or banked in, not the moment the colour is changed (a known Cubase limit), so a changed colour appears on the scribble strip after you select another track.
- **LED feedback.** Cubase reports a button's state as note on / off, and "on" has also been seen as polyphonic aftertouch with value 127. The bridge accepts both.
- **Fader touch** uses the MIDI Remote API 1.1 touch state, guarded so the script still loads on older Cubase versions.
- **Automation Read / Write** act on the selected track, because the UF8 buttons are global.

- **Hidden banks: names only.** The three hidden banks (track numbers, follow selection, recordable tracks) once bound a value per channel (selected, record-enable): 640 bound values. Cubase then paused for up to 0.7 s at a time while a value kept changing (traced while turning a send: its answers stopped, then everything was re-sent), which made the V-pots jerky. They now only collect names (`mOnTitleChange`), and the pauses are gone.
- **Lists slow down their own script's banking.** Even with names only, the UF8 script's two lists (256 + 128 channels) made each UF8 bank press take about 0.3 s instead of about 0.07 s (traced: press to the first new name). Cubase re-checks every channel of a script whenever that script's bank moves, but not other scripts' channels (the UF1's own 256-channel list made no difference to the UF8). So the lists live in the helper script; it sends the names (SysEx 18 / 19, 3 x 7 bits per character) and the bridge passes them on to the UF8 script. Until names arrive, the UF8 script asks for them every 2 s (SysEx 1B, passed on to the helper), as Cubase drops what is sent while a project loads.
- **Which UF8 strips can record.** The MIDI Remote API does not say what kind of channel a strip is, and Cubase even reports record-enable as "on" for a group after a press. So the helper script keeps a hidden bank with only the channel types that can record (groups, FX, VCA, inputs and outputs excluded, up to 128 channels) and passes their names to the UF8 script. A strip whose name is not on that list gets a dark, inactive top soft key. Two tracks with the same name, or more than 128 recordable tracks, can confuse it.
- **Cubase re-sends values.** When one bound value changes, Cubase often reports the others again unchanged, and it re-sends all strip names after a bank key. The scripts only act on values that really changed.
- **Following the selection (UF8).** Selecting a track that is not on the eight strips (for example in the MixConsole) banks the UF8 to it, and at start-up the UF8 goes to the selected track. Cubase moves its MIDI Remote banks to a newly selected channel by itself, in one move, but only in steps of eight from wherever the bank is: after Page left / right or banking near the end of the list the first tracks are out of reach, and at start-up it does not move at all. The script fills those gaps. A hidden bank of all channels (same types as the UF8 bank) gives each channel's position and name; the selected track is the one whose name is Cubase's current track (the one the UF1 shows), and the strips' names give the bank's position. Several tracks with that name: the one whose UF8 strip is selected, if it is on the strips; otherwise the one nearest to the previous selection. Switching between same-named tracks counts as a new selection (watched through the strips' SEL). 300 ms after a selection change (Cubase's own move first), if the selected track is still not on a strip, the script asks the bridge for a jump: bank reset (back on the eight-grid) and n bank-rights (SysEx 10). Half a second after a move it checks again; a jump that fell short is completed with one burst of the remaining steps (SysEx 0B / 0F with a count), a try that did not move the bank at all jumps again. The bridge freezes the UF8 during these bursts, so only the end shows. At start-up the script checks every second for 30 s (the first check 2.5 s after loading: Cubase ignores bank presses for a few seconds, sometimes longer) and holds the UF8 frozen until the selected track is on a strip (SysEx 13). With several tracks selected, the script follows Cubase's current track. Cubase has no "go to bank n", so a far jump takes about 0.1 s per bank (hidden, but the wait remains). Selecting a track from the script (setting `mSelected`) was tried as a way to trigger Cubase's own move; it selected the wrong track, so it is not used.
- **Timer: Cubase's idle callback.** The scripts have no timer of their own; `deviceDriver.mOnIdle` is called about ten times a second (measured) from the moment the project has loaded, and `Date.now()` works, so the follow-selection checks run from there.
- **Notes from the bridge cannot run script code; SysEx can.** A note bound to an action triggers that action in Cubase, but in testing the button's `mOnProcessValueChange` never ran for notes bound to a dummy bank's reset (notes 80 / 81), nor for one bound to the hidden bank's reset. SysEx does reach script code: `midiInput.mOnSysex` (the helper's names, SysEx 18 / 19 / 1B / 1C). Messages the other way (script → bridge) work, except while a project loads: Cubase then drops some of what the scripts send and receive.
- **Bank-right at the end (UF8).** The script reports the bank's size and position to the bridge (SysEx 12). Near the end, the bridge turns a bank-right press into single-channel shifts so the last track lands on strip 8; on the last full bank it does nothing. Until the size is known, bank-right is a normal step.
- **Track number (UF1).** Cubase does not tell scripts a track's number, so the UF1 script keeps a hidden bank of all mixer channels (same types as the UF8 bank), finds the selected track's name in it and sends its position (SysEx 0E). Several tracks with that name: the UF8 script tells which one is selected (its rank among them, top to bottom; SysEx 1C via the bridge), since Cubase only reports the name, which does not change between them. Without a UF8: the one nearest to the previous selection. A hidden track with the same name can still confuse it (the UF8 counts visible tracks only). The bank ignores visibility (`setFollowVisibility(false)`), so hidden tracks are counted and the number matches the MixConsole.
- **Sub-pages (UF1).** The UF1 page has two sub-page areas: *Strip* (selected track / main output, switched by MASTER) and *Sends* (sends 1–4 / 5–8, or Quick Controls 1–4 / 5–8, switched by 5–8 and the MODE view). The bridge activates them with notes 44 / 45 and 53 / 54 / 88 / 89 and keeps the key state and LEDs itself. The main output is the first channel of a one-channel bank that excludes every other channel type.
- **V-pots 1–4 (UF1) are absolute.** Bound as 14-bit CCs (17–20 + 49–52), absolute. The bridge keeps each V-pot's position, adds the turns itself and sends the new position, and draws it at once (as Rea-Sixty sets the value in REAPER itself); a relative step to Cubase and back lagged and wobbled. The script reports Cubase's position to the bridge (SysEx 17) on every change and once a second from the idle callback, so the bridge starts from the right value after loading or a track change.
- **SENDS view (UF1).** The script sends each send's name (the send slot's own title, i.e. the destination, without Cubase's "1- "; the V-pot itself only knows "1" and "Level") and level text to the bridge (SysEx 15). Names longer than 9 characters lose inner vowels first, then get cut ("Reverb Vocal" → "Revrb Vcl").
- **Quick Controls (UF1 PLUGIN view).** The V-pots are bound to `mHostAccess.mFocusedQuickControls`: the Quick Controls of the focused plug-in window, or the selected track's own when no plug-in window has focus. Only slots that have a parameter assigned do anything (many plug-ins fill only some by default; assign the rest in the plug-in window, or the track's in the Inspector). The value line shows the parameter name and value for 3 seconds, `QC<n>` for an unassigned slot. The V-pot pushes do nothing in this view.
- **Meters.** Cubase gives the meter as linear amplitude, so the scripts convert it to dB (`meterToMidi`, floor `METER_FLOOR_DB = -55`) before sending. Each channel's left and right meter is bound with `mValue.getVUChannelMeterByChannelIndex(0 / 1)` to a custom value variable and sent as CC (UF8: 80 + strip left, 88 + strip right; UF1: 80 / 81). If that call is missing, the scripts fall back to `mVUMeter` (one value) and log it.
- **API reference.** Cubase installs the exact API it offers as `midiremote_api_v1.d.ts` under `<Documents>\Steinberg\Cubase\MIDI Remote\Driver Scripts\.api\v1\`. Check names there before guessing (for example `mTransportLocator.mOnChange(activeDevice, activeMapping, time, format)`, `makeInsertEffectViewer(...).excludeEmptySlots().accessSlotAtIndex(i)`).
- **Command bindings.** `makeCommandBinding` needs the internal category and command name. They are in the `.xml` files under `Cubase 15\Presets\KeyCommands`; this prints the category of a command:
  ```powershell
  Get-ChildItem "C:\Program Files\Steinberg\Cubase 15\Presets\KeyCommands\*.xml" | ForEach-Object {
    [xml]$x = Get-Content $_.FullName
    $x.SelectNodes("//item[list[@name='Commands']]") | ForEach-Object {
      $cat = $_.SelectSingleNode("string[@name='Name']").value
      $_.SelectNodes("list[@name='Commands']/item/string[@name='Name']") | Where-Object { $_.value -like '*Bypass: Inserts*' } |
        ForEach-Object { "Category: $cat  ->  $($_.value)" }
    }
  } | Sort-Object -Unique
  ``` In use:
  - `Project` / `Select Track: Prev`, `Select Track: Next` (UF1 channel encoder, ARROW, BANK without a UF8)
  - `Transport` / `Nudge Cursor Left`, `Nudge Cursor Right` (UF1 jog)
  - `Zoom` / `Zoom In`, `Zoom Out`, `Zoom In Vertically`, `Zoom Out Vertically` (UF1 NAV cross, UF8 zoom pad)
  - `Editors` / `Open/Close Editor` (NAV / zoom pad centre; acts on the selected part or event, like a double-click)
  - `Mixer` / `Bypass: Inserts` — the name is right, but Cubase does not run it from a script; not every command can be bound (BYPASS uses insert viewers instead)
  - `Transport` / `Exchange Time Formats` (UF1 360°), `Locate Previous Marker`, `Locate Next Marker` (SHIFT + jog), `Step Back Bar`, `Step Bar` (SHIFT + ARROW), `Shuttle Play 1/8x` … `8x` and `Shuttle Play Reverse 1/8x` … `8x` (shuttle)
  - `Transport` / `Jog Left`, `Jog Right` — bound but no longer used (choppy audio; scrubbing goes through Mackie Control)
  - `Automation` / `Automation Mode - Cross-Over`, `Automation Mode - Trim` (a toggle), `Automation Mode - Auto-Latch`, `Automation Mode - Touch` (UF8 automation keys)

- **UC1: plug-ins through Direct Access.** `page.mHostAccess.makeDirectAccess(selected track channel)` gives the selected track's object tree (inserts, slots, plug-ins, strip, sends …). A plug-in's parameters are addressed by index (`getParameterTagByIndex`), and the order is the VST3 order, the same numbers Rea-Sixty uses (checked on Bus Compressor 2). `mOnParameterChange` reports changes from anywhere, `mOnObjectChange` plug-ins added or removed. Direct Access calls need the active mapping, which the SysEx handler does not get; the script keeps it from the page's callbacks. Channel Strip 2's Gate Threshold runs the right way in Cubase (Rea-Sixty turns it round). `makeDirectAccess(page.mHostAccess.mMixConsole)` gives the whole mixer (VST Mixer → channels, ~4400 objects in a 60-track project, searched in ~70 ms), with the same object ids; the script finds every bus comp there. It is not told reliably when a plug-in is added to a track that is not selected (Stereo Out), so the list is read again when the Bus Comp encoder turns after a 2 s pause and after plug-in changes on the selected track. Cubase's own channel strip is found by parameter name: input filter (`PreGain`, `LC-Freq`, `HC-Freq`, …), channel EQ (`EQ 1 Gain`, `EQ 1 Freq`, `EQ 2 Q`, …, `Bypass`), and the strip's Gate / Compressor modules (slots under `Strip`; release / attack skip the `Auto …` switches, and "Threshold" contains "hold"). Strip modules are loaded with the Direct Access plug-in manager: `trySetSlotPlugin(slot, classId)` where the class id is the module's unique name (`getObjectUniqueName`) without its `-<n>` ending; the strip slots list no plug-ins of their own, and switching a strip module's on switch (`mStripEffects.mGate.mOn`, bound to a CC the bridge sends back, SysEx 3A) does not load one. The EQ band types are read by setting each value for a moment and reading its name back (band 4: Parametric I, High Shelf I, Low Pass I / II, Parametric II, High Shelf II–IV). Stepped parameters (a ratio) snap small changes back, so a turn is added up while the knob is being turned. `getMixerChannelIndex` gives the MixConsole number as shown (not 0-based); hiding a track renumbers without a callback, so the script asks again every second.
