# Cubase-Sixty Bridge

A small Windows program that sits between the SSL controllers and Cubase:

- **USB side:** opens the UF8 and UF1 over their vendor-USB interfaces, using the device and protocol code from Rea-Sixty's `extension/src/` (`UF8Device`, `UF1Device`, `Protocol`, `UF1Protocol`, `Palette`, ...), compiled in place rather than copied.
- **MIDI side:** talks to the loopMIDI ports (through RtMidi) and translates between SSL frames and the messages in [`../docs/bridge-midi-protocol.md`](../docs/bridge-midi-protocol.md). The Cubase end is the MIDI Remote scripts in [`../midi-remote/`](../midi-remote/).

SSL 360° must not be running: it claims the controllers' USB interfaces exclusively. Each surface is optional; the bridge skips a surface whose device or ports are missing and says so.

## Status

| Surface | Working |
|---------|---------|
| UF8 | Faders (motor, touch, echo suppression), SEL / SOLO / CUT with LEDs, top soft keys = record-enable (red; dark and ignored on strips that cannot record), V-pots (pan) with the pan value and bar on the display, V-pot push, banking (bank-right stops at the bank where the last track is on strip 8), Page left / right (shift the bank by one channel), follows the track selection (also at start-up; jumps show as one switch), automation Read / Write with LEDs, automation mode keys (Off = Cross-Over, Trim, Latch, Touch), zoom pad (left / right = zoom, up / down = vertical zoom, centre = open / close editor), FLIP (faders on pan, V-pots on volume), scribble-strip names and colours, fader level in dB on each strip, stereo meters, empty strips dark (SOLO / CUT / SEL LEDs off, late values ignored). Foot switches are implemented but untested. |
| UF1 | Fader (motor, touch), SOLO / CUT / SEL (SEL LED in the track colour), transport keys with LEDs, ARROW = previous / next track, BANK = banks the UF8 (8 tracks without a UF8), NAV cross = zoom (centre = open / close editor), pan knob above the fader, MODE (hold) picks the view on the display soft keys: DAW = V-pots 1–4 on sends 1–4, or 5–8 after the 5–8 key (turn = level, push = on / off), SENDS = the same, with all four sends in the display's V-pot cells (name, level, bar), PLUGIN = the selected track's SSL plug-in in pages (see below), or V-pots on Cubase's Quick Controls 1–4 / 5–8 without one, METER = the SSL Meter (Pro) plug-in's Overview screen (bar meters, peak / RMS readouts, overload, Lissajous; soft key 2 RESET), MASTER puts fader, pan, SOLO and CUT on the main output, SHIFT + the transport soft keys / Cycle / Click = automation (◀ Read, ▶ Write, Cycle Cross-Over, Click Trim, 1 Latch, 2 Touch), FLIP (fader on pan, pan knob on volume), channel encoder selects the previous / next track, jog wheel nudges the cursor (SHIFT + jog = previous / next marker, SHIFT + ARROW = one bar back / forward), SCRUB = real audio scrubbing through a Mackie Control device, SHIFT + SCRUB = shuttle (the jog sets the speed), 360° swaps Cubase's two time formats, BYPASS = bypass / restore all inserts of the selected track. | UC1 | Opens with Rea-Sixty's handshake, start-up sequence and keepalive (its own MIDI ports). Knobs and buttons go to the UC1 script, which drives the SSL plug-ins on the selected track; the bridge paints the track name and colour, the model field, value readouts, button LEDs and the knob rings (Rea-Sixty's cell maps). The 7-segment shows the MixConsole number; the Bus Comp encoder picks which bus comp the Bus Comp section controls (name row, "BUS COMP 2" header for 1.5 s). Encoders count one step per detent (Rea-Sixty's accumulator). The magnifier steps through a track's channel strips, 360° opens their window (both in the script, with CCs the bridge sends back, SysEx 3A). The PRESETS screen is the bridge's own (Rea-Sixty's screens; SSL's preset library read from `%ProgramData%`); the values go to the script to set. The ROUTING screen too (Rea-Sixty's ten orders). ## Building

Requires Visual Studio Build Tools (MSVC), CMake and [libusb](https://libusb.info) (the Windows binary release). RtMidi is fetched automatically.

```
cmake -S cubase\bridge -B cubase\bridge\build -DLIBUSB_ROOT=C:/path/to/libusb
cmake --build cubase\bridge\build --config Release
```

`LIBUSB_ROOT` is the folder that contains `libusb.h` somewhere below it and `VS2022\MS64\dll\libusb-1.0.lib`. Stop the running bridge before rebuilding, or the link step fails with LNK1104. The result is `cubase\bridge\build\Release\cubase_sixty_bridge.exe` (with `libusb-1.0.dll` next to it). `build\` is git-ignored.

A small test program checks the note, LED and colour mapping without hardware:

```
cubase\bridge\build\Release\test_mapping.exe
```

## Running

1. Install loopMIDI (its driver is what lets the bridge create MIDI ports; you do not create any ports in it yourself), the Cubase scripts and the Mackie Control device for scrubbing, as described in [`../midi-remote/README.md`](../midi-remote/README.md).
2. Start the bridge **before** Cubase:
   ```
   cubase\bridge\build\Release\cubase_sixty_bridge.exe
   ```
3. Start Cubase. It sees the ports, activates the scripts and sends the current state (names, colours, faders, LEDs, display) to the running bridge.
4. If you restart the bridge, restart Cubase too: it does not pick the ports up again when they disappear and come back (neither **Reload Scripts** nor the refresh button in the MIDI Remote Manager helps).
5. If a surface still does not respond, restart Cubase with the bridge running.
6. **Stuck MIDI ports.** After many bridge restarts in one Windows session, the MIDI layer can get stuck: the bridge sends fine, but nothing from Cubase arrives (with `--trace`, no `[virtual port in]` lines at all; the screens stay blank, the UF1 keeps showing READY). Sometimes ports get garbled names. Restarting the PC clears it.

Options:

| Option | What it does |
|--------|--------------|
| `--trace` | Prints UF1 events, the MIDI the UF8 and UF1 send to Cubase (not fader positions), every UF1 LED change, UF1 value-line updates, and the UF8 record-enable state per strip. |
| `--loopmidi` | Use ports made in loopMIDI (the old way) instead of creating them. The bridge does this by itself if loopMIDI's driver library (`teVirtualMIDI64.dll`) is missing or cannot create a port. |
| `--lamptest` | Lights each UF1 LED in turn about 6 seconds after start-up. |
| `--no-script-log` | Do not write the scripts' log lines to `cubase\logs\scripts.log` (see Logs). |

### SSL 360 Core

The bridge stands in for SSL 360 Core, so the SSL plug-ins send it their meters (UC1 gain reduction). SSL's own `SSL360Core.exe` must not run: it takes the controllers and, if it is there first, the plug-ins. The SSL plug-ins start it again when they cannot find a Core, so the bridge closes it at start-up and whenever it reappears (seen: with it running, only 6 of ~60 plug-ins reached the bridge). Each plug-in announces the MixConsole number of its channel, which is how the meters are tied to tracks. Windows: the bridge starts Windows sockets itself (REAPER does it for Rea-Sixty).

### Logs

The bridge writes two files to `cubase\logs\` (ignored by git):

- `bridge.log`: everything the bridge window shows (with `--trace`, the trace too), each line with a timestamp.
- `scripts.log`: the MIDI Remote scripts' log lines (what Cubase's script console shows), sent to the bridge as SysEx 7E; each line with a timestamp and the script (UF8, UF1, UC1, Helper). Off with `--no-script-log` (`dev-restart.ps1 -NoScriptLog`).

Rea-Sixty's own logs (`rea_sixty.log`: the Core stand-in's start, each plug-in's connection and announced track; with `--trace` also `reaper_sslcore.log` and `reasixty_ssl_objects.log`, the plug-in traffic) land there too.

Each start begins new files and keeps the last run's as `*.previous.log`; a file that passes 20 MB starts again, keeping the older part as `*.log.old`.

## Behaviour to know about

- **Foot switches.** An unplugged foot-switch jack reports itself as "pressed" while the UF8 starts, which used to start the transport. The foot switches are ignored for the first 4 seconds.
- **MIDI ports.** The bridge creates the four ports (`Cubase-Sixty UF8|UF1 to|from Cubase`) with loopMIDI's driver library while it runs; they disappear when it exits. Delete any ports with these names that you made in loopMIDI earlier. Cubase may tick **In 'All MIDI Inputs'** for a port it sees as new; untick it (see the MIDI Remote README). In the `--loopmidi` fallback, Cubase sends state only when it changes, so a bridge that starts after Cubase sees nothing: if nothing has arrived 2.5 seconds after start-up, the bridge presses bank-next and bank-previous on the UF8 to make Cubase resend (if Cubase is on its last bank the UF8 ends up one bank back), and for the UF1 you press **Reload Scripts**.
- **Opening the surfaces.** Each surface's USB device gets three tries, 2 seconds apart ("trying again (2 of 3)"). If the UF1 stops answering later (it can miss the wake right after the previous bridge let go of it), the bridge closes and reopens just the UF1, keeps the MIDI ports, and replays the last name, colour, values, time and LED states Cubase sent ("UF1 reopened"). The UF8 is handled the same way: if it stops answering, the bridge reopens it and replays the last names, colours, pan, dB texts, faders and LEDs ("UF8 reopened"); if that fails, the bridge exits and says why.
- **Mackie Control ports (scrubbing).** The bridge also creates `Cubase-Sixty MCU to Cubase` / `... from Cubase` for a Mackie Control device in Cubase. Only two things go over it: SCRUB (Mackie note 101, which toggles Cubase's scrub mode; its LED feedback keeps the UF1's SCRUB LED in step) and the jog while scrubbing (Mackie jog, CC 60, one tick per detent). Everything else Cubase sends to that device is ignored. Without those ports SCRUB falls back to fast nudging. Cubase's own `Jog Left / Right` commands were tried first and played choppy audio.
- **Shuttle.** SHIFT + SCRUB: each jog step changes the speed through Cubase's Shuttle Play commands (1/8× … 8×, and the same in reverse through zero; zero = Stop). Leaving shuttle stops playback. SCRUB LED: white = scrub, orange = shuttle.
- **BYPASS (UF1).** The script reads every insert slot of the selected track (insert viewers, `accessSlotAtIndex`) and reports one state: no inserts (LED off), inserts active (LED orange at 35 %), all bypassed (LED full orange). A press bypasses all slots, or restores all; the bridge sends each slot its new state on MIDI channel 2, notes 0–15 (channel 1 collided with the transport notes and started playback). Binding one key to all slots' bypass did nothing in Cubase.
- **Time display (UF1).** The transport position (`mTimeDisplay.mPrimary.mTransportLocator.mOnChange`) goes to the 7-segment field, right-aligned; Cubase's padding spaces stay as blank cells so digits do not shift, a ':' becomes a blank cell, '.' stays the decimal / bars-beats dot, and leading zero hours are dropped when the text does not fit in ten cells. The seconds format (`H:MM:SS.mmm`) is shown as blank-separated groups, hours and minutes only when they are not zero: `47 691`, `3 47 691`, `1 03 47 69` (milliseconds cut to fit). 360° runs `Transport / Exchange Time Formats` (the API has no "next format" action), so it swaps the primary and secondary clocks.
- **FLIP.** UF1: four strip sub-pages (selected / main output × normal / flipped). UF8: two sub-pages. Under FLIP the value line still shows pan (now from the fader) and the dB field the volume (now from the knob).
- **Helper ports.** With the UF8 open, the bridge also creates `Cubase-Sixty Helper to Cubase` / `from Cubase` for the helper MIDI Remote script, which holds the UF8 script's large channel lists (they made each UF8 bank press about 0.25 s slower inside the UF8 script). The bridge passes the helper's names (SysEx 18 / 19) on to the UF8 script and the UF8 script's requests (SysEx 1B) on to the helper, and the UF8 script's same-name rank (SysEx 1C) on to the UF1 script. Without the helper ports the UF8 does not follow the selection and its record keys stay dark.
- **Following the selection (UF8).** The UF8 script decides (see the MIDI Remote README); the bridge sends the presses: a jump (SysEx 10: bank reset, note 79, then n bank-rights) or a burst of bank steps (SysEx 0B / 0F with a count), 100 ms apart (at 60 ms Cubase merged presses). Cubase has no "go to bank n", so a far jump takes about 0.1 s per bank.
- **UF8 freeze.** During a jump or a burst the UF8 is frozen: what Cubase sends for the banks passed on the way (names, colours, pan, dB texts, faders, LEDs, meters) is only cached, and 400 ms after the last press the cached end state is shown once (the same replay as after a reopen), so a jump looks like one switch. At start-up the script holds the freeze across several tries (SysEx 13 01 / 00), because Cubase ignores bank presses for a few seconds after loading a project; the bridge releases a held freeze by itself after 30 s.
- **Bank-right at the end (UF8).** A bank-right from the UF8 key or the UF1's BANK checks the bank size the script reports (SysEx 12): with fewer than eight tracks left after the last strip, the bridge sends that many Page-right shifts instead, so the last track lands on strip 8; on the last full bank it does nothing. Unknown size: a normal step. The follow-selection jump still uses plain bank steps.
- **Record-enable keys.** Dim red = can arm, bright red = armed, dark = this strip cannot record (group, FX, VCA, bus, empty strip); a dark key ignores presses. The script decides which strips can record (see the MIDI Remote README). An audio track with no input bus still shows dim red but Cubase will not arm it.
- **Encoder speed (UF1).** The channel encoder and the jog wheel send one step per 4 detents (`kDetentsPerPulse` in `Uf1Bridge.cpp`).
- **UF1 SEL LED.** Shows the selected track's colour at 35 % (`kSelDimPct`; the UF1's own dim level did not dim visibly), full brightness while the channel editor is open.
- **UF1 BANK and ARROW.** BANK presses the UF8's bank key when a UF8 is running; without one it steps the selection 8 tracks (40 ms apart, back-to-back steps were merged by Cubase). ARROW is one channel-encoder step.
- **UF1 MODE.** Held, the four display soft keys show the view picker as in Rea-Sixty: soft key 1 PLUGIN, 2 DAW, 3 METER, 4 SENDS (labels at cell 0x0104 with the key index first, LEDs 0x01–0x04: the active view yellow, the others dim yellow). Releasing MODE blanks the keys again (in METER: the meter's own OVERVIEW / RESET / FINE / PRESETS). Key 1's LED gets no FF39 frame (Rea-Sixty: it sticks the key's rectangle on). The view and the 5–8 state together pick the V-pots' page (notes 53 / 54 / 88 / 89). The bridge keeps the view; when the script starts (Cubase started, scripts reloaded) it asks for the V-pot page (SysEx 54), and picking a view always sends its page again.
- **UF8 selection modes.** The NORM / REC / AUTO keys (ids 0x70 / 0x71 / 0x72, handled in the bridge, as Rea-Sixty's selection modes) set what SEL does: NORM selects the track (SEL's own note), REC toggles its record-enable (the press goes out on the top soft key's note, 48 + strip; ignored on strips that cannot record), AUTO toggles its automation Write (note 112 + strip, which the script binds to the channel's Write). The key of the mode is lit (Rec red). In REC the SEL LEDs work as the top soft keys (dark where the track cannot be armed, dim red where it can, red when armed); in AUTO the SEL LED is red while the track is writing (from the top soft key's feedback / note 112 + strip); NORM shows the selection again. Not yet: REC + MON, the cycle modes, "only tracks armed for writing".
- **UF1 METER view (Overview).** Ported from Rea-Sixty (Uf1Meter.cpp; the codecs in Uf1MeterCodec.inc are Rea-Sixty's, unchanged). The values come from an SSL Meter or Meter Pro plug-in through the SSL 360 Core stand-in (started when the view opens if the UC1 has not started it; SSL360Core.exe is closed every 3 s while the view is open). The meter of the selected track is shown (the plug-ins announce their MixConsole number); a track without one keeps the last meter shown, so a Meter on the Stereo Out shows whatever is selected. Entering sends Rea-Sixty's Overview entry burst (0x0100 = 04 00 = Meter layout, Overview screen); each 40.8 ms cycle then carries the goniometer image (35 × 0x0122, from the plug-in's Lissajous), the meters (0009 still carries the track level for the small display), and the tail: 011c readouts (peak hold, peak L/R, RMS hold, RMS L/R, 25 bytes each), 0125 RMS bars, 0126 peak bars, 0127 hold bars, 0128 overload mask, 011d = 00. Setting cell 1 (0x010e slot 0) shows the track of the meter shown, NO METER without one. Soft key 2 RESET clears the plug-in's peak holds and overloads (and flashes its key). V-pots do nothing in METER (no meter settings yet). Leaving restores the channel layout (Rea-Sixty's channel entry frames, 0x0100 = 03 00) and draws the channel view again from what Cubase sent last. Not yet: Analogue / RTA / Loudness screens, V-pot settings, FINE, PRESETS, the plug-in's Digital Type (the bars use the Non-Linear scale).
- **UF1 PLUGIN view.** The UF1 script finds the selected track's SSL plug-in (a channel strip first: Channel Strip 2, 4K B / E / G, 360 Link; else a Bus Compressor 2 / 360 Link Bus Compressor) through Direct Access and lays its controls out in Rea-Sixty's pages (SSL's UF1 User Guide p188 tables, as measured on SSL 360 2.1.12: 8 pages for CS 2 and Link, 10 for the 4Ks, 2 for the bus compressors). Parameters are found by name. The script sends the plug-in (SysEx 50), the four V-pot cells (51) and the four soft keys (52); the bridge draws them: cells as in SENDS (bipolar controls such as EQ gains and trims as a centre bar, style 08), soft-key labels with the LED lit white while the switch is on (SSL's Ø glyph is 0x7F on the wire, 0xD8 in the UF1 font), the page "N/M" in the header's SOFT KEY field, the plug-in's name in the header's CHANNEL field (without an SSL plug-in: what the Quick Controls belong to, from SysEx 56; "Cubase QC" for the track's own Quick Controls (Cubase reports the track's name) or when Cubase does not say; the field shows 13 characters), the model in the CS TYPE cell. V-pot turns and pushes, soft-key presses and ◀ ▶ go to the script as SysEx 53 (the channel encoder still steps the track); a V-pot step is 2 % of the range, a push puts a bipolar control back to the centre. The EQ graph (0x0122) shows the channel strip's own EQ curve, which the plug-in sends to SSL 360 Core (read from the stand-in, matched by MixConsole number, model and the strip's position among the track's channel strips, as Rea-Sixty does), redrawn every third cycle when it changes; flat while the EQ is out. On a track without an SSL channel strip the graph shows Cubase's own channel EQ and input filter instead: Cubase sends no curve, so the script sends their settings (SysEx 55) and the bridge draws the curve with Rea-Sixty's renderer (Uf1EqCurve: bells, shelves, cuts with their slope; the cut types' I / II read as 12 / 24 dB per octave, an approximation). Without an SSL plug-in the cells show the Quick Controls' names and values, and ◀ ▶ switch between Quick Controls 1–4 and 5–8 (as the 5-8 key does). With a UC1 the PLUGIN view follows the strip its magnifier key picked (SysEx 41 from the UC1 script, passed on as 57); Cubase's own strip there means Quick Controls and Cubase's EQ curve. Not yet: Cubase's own channel strip on the V-pots, the label-only keys (SOLO SAFE, PLUG-IN, HQ MODE, A/B, S/C MODE: no parameter behind them in Cubase), jumping to the page of a control touched in the plug-in window, the 360 Link's and 32C's special cases.
- **UF1 FINE.** Quick key 2 (without SHIFT) switches FINE, as in Rea-Sixty: the V-pots move a quarter as far per detent (sends, Quick Controls and the SSL plug-in's controls). The header's FINE CTRL field shows ON / OFF.
- **UF1 preset browser.** SHIFT + 5-8 (in the channel views) opens Rea-Sixty's preset browser for the track's SSL plug-in: SSL's preset library on disk (shared with the UC1's PRESETS screen, SslPresets.cpp), drawn in the big display (layout 0x0100 = 04 03; the header row's field 0 = the plug-in, fields 1–7 = a window with the selection on the middle row, which the firmware highlights; 0x011f = the scrollbar). The idle cycle pauses while it is open (Rea-Sixty pauses its pacer) and its frames are restated every 40.8 ms instead. V-pot 4 scrolls (3 detents per preset), its push (Select) loads the preset (SysEx 3C / 3D to the UF1 script) and closes the browser; soft key 3 (Navigate Back), SHIFT + 5-8 again or picking a view closes it. It opens on the preset loaded last for that plug-in.
- **UF1 SENDS view.** The four V-pot cells of the big display show sends 1–4 (or 5–8): name left, level right (Rea-Sixty's value line, 19 characters: cell 0x010e with the pot index first), the bars in 0x010f (position 0..100 + 0x80 per pot) with the pointer style in 0x010d (0x03 = empty pot). Only what changed is sent. The temporary send readout on the small value line is skipped in SENDS (the cell shows it). Outside SENDS the cells are blank.
- **UF1 idle cycle.** The big display draws continuously only while it gets SSL's cycle without a break (Rea-Sixty, `uf1CyclePacerLoop_`): every 40.8 ms a meter group (0009 level, 000a, 0015, 0016) 18 ms in and a closing frame (011d = 11) at the end, with silences in between. Without it the firmware draws only when the traffic pauses: the V-pot cells started smooth and then turned choppy. The bridge streams this cycle from the moment the UF1 is open, using Rea-Sixty's `Uf1Pacer` (now part of the build); the level meter rides in it, and everything else sent meanwhile is held by `UF1Device` and goes out right after each cycle (up to 40 ms later).
- **UF1 V-pots owned by the bridge.** V-pots 1–4 are absolute in Cubase (14-bit CC). The bridge keeps each one's position (0..16383, from the script's SysEx 17; ignored for 0.5 s after a turn, so Cubase's echoes do not pull it back), adds 82 per detent and sends the new position. The SENDS bars draw that position at once. The level text comes from Cubase and lags, so the bridge learns Cubase's level curve: each position Cubase reports is stored with the text Cubase sent just before it. While a V-pot turns, the cell shows the text for the bridge's own position (Cubase's text for that exact position, or interpolated between stored positions up to a quarter of the range apart, two decimals below 10 dB); 0.5 s after the turning stops, Cubase's own text again. The curve is learnt in DAW and SENDS (not PLUGIN) and starts empty with each bridge start.
- **UF1 value line.** Pan is the line's normal content. Turning a send V-pot shows that send for 3 seconds after the last change (`kTemporaryMs`); selecting another track shows its pan straight away.
- **Automation mode LEDs (UF8).** Cubase does not tell scripts which global automation mode is active, so the bridge lights Off / Latch / Touch from the last one pressed (on the UF8, or SHIFT + key on the UF1) and Trim as a toggle. All dim at start-up; a mode changed with the mouse is not seen. Off (Cross-Over) is purple; like the Auto, Plug-in and Page keys it needs the legacy LED frame (`buildLedCommand`) besides the colour pair, kept "on" so the colour pair can show dim.
- **Meters.** Cubase reports the meter as linear amplitude (0–1); the scripts convert it to dB and map −55…0 dBFS onto 0–127 (`METER_FLOOR_DB` near the end of each script), the same scale Rea-Sixty uses on the UF8. Left and right per channel; a mono channel (only a left value) is shown on both sides. The UF8 meter frames are throttled like Rea-Sixty's (a byte moved by 2, or 50 ms passed) so faders and LEDs do not lag during playback. Empty strips are cleared and ignore late values.
- **dB readout (UF8).** Each strip shows its fader level. Cubase does not resend a level that equals what the strip showed before it went empty, so the bridge keeps the last text per strip and shows it again when a track returns.
- **UF1 colour bar.** At start-up the bridge writes 12 spaces to the text cell inside the colour bar (Rea-Sixty's "nothing"; an empty text drops the layer), clears the channel number, and sets the peak indicator and the compressor / gate gain-reduction cells to rest. The dimmed block at the left of the colour bar is the channel-number box, which the firmware always draws; it shows the selected track's number from the script (SysEx 0E, counted like the MixConsole), the UF8 strip (1–8) of the selected track when the number is not known, and nothing when MASTER is on.
- **UF1 display cell 0x0000.** Never write it: Rea-Sixty found that it belongs to the display's plane setup and writing it tore the layout down. The key above the display has its own LED (id 0x00).
- **LEDs.** The UF1 buttons are lit by colour (an LED with colour black is off), as in Rea-Sixty. LED brightness is set to full when the UF1 opens.

## Development

`cubase\tools\dev-restart.ps1` restarts the whole chain in the right order: closes Cubase (resending Quit until it exits), ends Cubase processes that are left without a window after 15 seconds (an unfinished shutdown; they cannot be showing a dialog), stops the bridge and waits 3 seconds for Windows to release the devices and ports, optionally rebuilds it, installs the scripts, starts the bridge (up to three times, if it exits straight away), then opens your test project. Cubase is quit with Ctrl+Q directly, so it does not show the Hub on the way out. If the bridge does not stay up, Cubase is not started; run `cubase\bridge\build\Release\cubase_sixty_bridge.exe` by hand to see why.

```
powershell -ExecutionPolicy Bypass -File cubase\tools\dev-restart.ps1 -Build
```

Options: `-Build`, `-Trace` (bridge with `--trace`), `-Force` (kill Cubase after 60 seconds; unsaved changes are lost), `-NoStartCubase`, `-Project <file.cpr>`, `-CubaseExe <path>`. The project is, in this order, `-Project`, the environment variable `CUBASE_SIXTY_PROJECT`, or the first line of `cubase\tools\project.txt` (a local file; do not commit it). Without a project, Cubase opens on the Hub.

## Risks

- **MIDI Remote API limits** (focused plug-in access, metering, live colour updates) are the main unknown.
- **Licences:** Rea-Sixty's licence, and the Steinberg VST3 SDK terms if a probe plug-in is ever written.
